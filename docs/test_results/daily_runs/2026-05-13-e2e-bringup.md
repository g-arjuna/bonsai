## Issues Found and Fixed This Session

### 1. ContainerLab TLS cert split-brain (both environments)
**Root cause**: `containerlab destroy` without `--cleanup` preserves `.tls/` directory.
Subsequent `containerlab deploy` reuses the old CA. Nodes from older deploys have certs
from a different CA keypair. Bonsai can only trust one CA → partial subscriptions.

**Fix**: Always use `containerlab destroy --cleanup` before `containerlab deploy`.
**Scripts**: `scripts/lab/redeploy_dc.sh` (laptop), `scripts/lab/redeploy_cloud_dc.sh` (cloud).

### 2. docker/configs/lab-dc.toml missing role/site fields
**Root cause**: Original config had no `role`/`site` per target — topology API returned
empty strings and the UI showed disconnected devices with no labels.

**Fix**: Added `role = "super-spine"/"spine"/"leaf"` and `site = "lab-dc"` to all 8 targets.

### 3. docker-compose.yml bonsai-cloud-dc service not committed
**Root cause**: Service was created but never staged/committed. Cloud git pull got a
compose file without the cloud-dc profile → "no service selected" error.

**Fix**: Committed `bonsai-cloud-dc` service in `fe8b620`.

### 4. day0_readiness.sh GITHUB_TOKEN check fails in non-interactive shells
**Root cause**: Script checked `${GITHUB_TOKEN:-}` directly. Cron and Claude Code
subprocesses don't inherit the interactive shell's exports.

**Fix**: Script now auto-sources `~/.bonsai.env` or `/opt/bonsai/instance.env` before
the token check, then validates via GitHub API (`GET /user`) instead of running
`daily_sync.sh --dry-run` (which fails on laptop due to cloud-only `/mnt/bonsai-archive`).

### 5. Cloud ARM64 Docker image missing
**Root cause**: Previous session's ARM64 build didn't persist. Image had to be rebuilt
natively on cloud (`docker build -t bonsai:latest -f docker/Dockerfile.bonsai .`).

**Fix**: Built successfully (168MB ARM64 image). For future deploys, pull from GitHub
and rebuild — there is no registry, cloud must build locally.

## Architecture Notes (memory-burned)

- **mode=all is temporary**: Current deployments use single-process `mode=all` for
  simplicity during the 7-day proof. Future bringups should use `distributed` profile
  (`bonsai-core` + `bonsai-collector-1`). See `project_distributed_arch.md`.
- **`collectors_connected: 0`** is expected with `mode=all` — not a bug.
- **`unassigned_devices: N`** in all-mode is a display artifact — devices ARE subscribed.
- **CA cert path**: docker-compose mounts `./lab/dc/clab-bonsai-dc/.tls/ca/ca.pem` as a
  live bind mount. The legacy `scripts/extract_lab_ca.sh` (copies to static `lab/dc/ca.pem`)
  is superseded and should not be used.
- **bv5_daily_check.sh** does not need GITHUB_TOKEN — safe to run from cron without
  sourcing instance.env.

## BN-003 acceptance gaps

1. **Normal production login/server path is not exercised.** The test invokes
   `build_public_routing_web_router`, a new standalone router with its own
   `public_login_handler`/`public_logout_handler` and hardcoded setup status.
   Source search finds this constructor used in tests, not production startup.
   Production mounts `auth::login_handler`/`logout_handler`. The duplicate handler
   omits parts of production login behavior, including its rate-limit and LDAP
   flow. Share production authentication handlers/router construction and run
   browser acceptance through the normal application path.
2. **Cookie issuance is not validated end to end.** Playwright obtains the JWT
   from response JSON and calls `context.addCookies`; later journeys also install
   the cookie manually. Cookie authentication consumption works, but the browser's
   processing of `Set-Cookie` is bypassed. Perform login via the browser or its
   context-bound request API, inspect the issued cookie, then navigate without
   manual token injection. Include logout/session denial checks. The source emits
   the stated cookie attributes, but that alone is not the claimed browser proof.
3. **VRF route data is synthetic.** The orchestrator calls
   `build_rd_bmp_frames` and directly ingests the `65000:100` / `10.99.1.0/24`
   frames. It does not configure a corresponding FRR VRF and capture its exported
   BMP. Label this as fixture/browser-filter coverage or add actual router VRF
   evidence. Assert excluded global/other-VRF rows, not just presence of the
   selected RD. Both exporters connect live, but browser assertions require only
   exporter `.11`; add explicit `.12` assertions and source-isolation checks.
4. **Restart is not a process lifecycle gate.** `handle_routing_restart` aborts
   the HTTP task, creates a new `RoutingServiceState` and rebinds HTTP in the same
   process. BMP readers/control context keep the old state. This proves journal
   reload and browser visibility, not restart of the deployed collector/service
   or ingestion after restart. Restart the actual service process and verify
   newly received routes and epochs after recovery.
5. **EOF and negative-state assertions are incomplete.** The control handler
   directly calls `record_transport_disconnect`; the test reader simply breaks
   on EOF/errors. This tests gap rendering after a collector-side close, not the
   production collector's EOF detection path. Verify no new withdrawal events
   and unchanged route counts, not merely one surviving prefix. Reconnect currently
   asserts only that the badge lacks `gap`; it could pass on another bad state.
   Assert the expected epoch and explicit completeness state, plus graph checkpoint
   and representative projected entities. Timeline checks require announce/withdraw
   and NH/AS text, not an attribute-change row with exact before/after values.
6. **Evidence needs stronger provenance.** The manifest lists requirements rather
   than per-criterion assertions and has no source revision/diff hashes. A SHA-256
   file names `captured_bmp_stream.bin`, but the runner never writes that binary;
   the hash cannot be independently recomputed from the supplied bundle. Save raw
   stream bytes (preferably per exporter/session), record fixture provenance,
   source hashes and actual Playwright results. Chromium revision is hardcoded;
   allow discovery/override instead of requiring one user's cached installation.

The claim that navigation to `/#/routing` itself returns HTTP 401 is inaccurate.
The hash fragment is client-side, static UI is explicitly permitted by middleware,
and the test asserts 401 on the API plus an error alert in the loaded UI.

## BN-001/002: remaining behavior reproduced

[Probe source](evidence/2026-10-13-bn003-review/executor-probes.rs) and
[probe results](evidence/2026-10-13-bn003-review/executor-probes.log) assert observed
undesirable behavior. Convert them to safe-behavior regression assertions when
implementing fixes.

- **Two simultaneously opened executors acquire the same scope.** Each loads its
  own in-memory map. Executor A persists owner A; executor B, opened before that
  acquisition, still accepts owner B for the same device/VRF. Reopening after a
  lock is written correctly recovers it, but concurrent exclusion is absent.
  The probe uses two independent instances in one process; the implementation has
  no interprocess journal lock or atomic shared compare-and-acquire. The submitted
  suite contains no process-spawn/kill test. BN-001 requires cross-process safety,
  not just sequential reopening.
- **Assurance fidelity can be changed without invalidating approval.** With a
  genuinely signed approval, enforced execution rejects a modeled report. Changing
  only `assurance.fidelity` to `LiveContainerlabVerified` makes the same execution
  succeed. The report ID/hash binding does not authenticate its content or origin.
  BN-002 needs a trusted immutable report store or verified assurance attestation;
  a caller-supplied enum does not prove live assurance provenance.
- **Completed replay returns before enforcement checks.** A completed simulation
  replay is accepted after switching to enforced mode without signing authority.
  This does not perform a new device write; it exposes a policy boundary: decide
  and enforce whether cached completion access requires current authority and
  whether simulation results can be replayed as enforced results.

Source review also finds ignored persistence errors on `LockReleased` and
`ExecutionAborted`, optional file backing in enforced mode, and acceptance of an
empty approval tenant ID. These paths are not closed by the three probes above;
include explicit failure-path tests and fail-closed rules before declaring BN-001
and BN-002 complete. Length-prefixed signing, key metadata binding, tail repair,
strict replay-plan binding and completion-before-memory updates are real fixes.

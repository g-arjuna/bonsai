## 1. Product decision

Bonsai should be the governed, temporal network-evidence and assurance service for any agent, not another mandatory agent orchestration framework. Make deterministic domain capabilities first-class; MCP is the standard tool/data interface, REST/OpenAPI and existing internal APIs remain, A2A is an optional task delegation facade to the same investigation runtime. A model is an untrusted consumer/proposer; an authenticated agent is not automatically authorized to see data or execute changes. No direct database credentials or collector access for agents. Preserve routing journals as authority and Ladybug as evidence/state projection; do not duplicate stores merely for protocol modernization.

Three boundaries: (1) acquisition and source identity; (2) trusted evidence assembly, deterministic computations and policy; (3) consumer-specific disclosure and audit. Every northbound and outbound path must use the same effective policy, not a weaker adapter. Deploy initially as Core-owned logical modules; separate processes only if measured resource/isolation needs warrant. MCP statelessness does not make embedded graph multiwriter or prove HA.

```text
External agent frameworks / NOC / SOAR / ITSM
    | MCP modern/legacy, REST; optional A2A read-only task facade
    v
Core agent gateway: identity -> policy -> admission -> typed capability registry
    |                               | policy / audit / UI / quotas
    v                               v
Deterministic evidence and investigation service -> disclosure gate -> response
    |                             |                     |
    |                             |                     +-> approved provider/agent
    |                             +-> durable audit / authorized evidence handles
    v
Ladybug graph + canonical routing history + bounded metric/history adapters
    ^
Authenticated collectors and trusted exporter bindings
```

A separate outbound broker mediates LLM, embeddings, enrichment, MCP clients, A2A and callbacks. No provider call, raw export or cross-agent handoff bypasses policy. Private/self-hosted inference is still a destination with a policy; never imply that cloud data can be recalled after disclosure.

## 3. Standards baseline and conformance contract

**October 2026 means MCP 2026-07-28 final**, not the 2025 handshake plus newer version string. [Final specification](https://modelcontextprotocol.io/specification/2026-07-28), [release notes](https://blog.modelcontextprotocol.io/posts/2026-07-28/), [transport](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports), [authorization](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization), [tools](https://modelcontextprotocol.io/specification/2026-07-28/server/tools). Freeze exact schema/revision, SDK and test-suite commits at implementation. Maintain explicit 2025-11-25 legacy profile only if clients need it; 2024-11-05 bespoke compatibility isolated and sunsetted, no unvalidated version advertisement. Future drafts are research only.

| Requirement | Implementation/acceptance |
|---|---|
| Modern request/response | JSON-RPC 2.0 validation, request ID and notification semantics; per-request protocol metadata and capabilities, server/discover, response serverInfo metadata, supported version error; no mandatory initialize or protocol session in July profile. Validate required fields against final schema rather than RC. |
| Streamable HTTP | UTF-8, negotiated media types, single endpoint POST, JSON or request-scoped SSE according to profile, correct HTTP status/errors, Mcp-Method and conditional Mcp-Name header/body agreement, protocol version headers where specified; origin validation independent of CORS; cancel/timeout/disconnect and admission until worker actually exits. No session affinity assumption. Legacy lifecycle separated. |
| Discovery and caching | Stable deterministic listing, pagination, schema validation, capability declarations only for implemented methods; private/no-cache initially (ttlMs 0, cacheScope private), later bounded policy/principal/scope/version cache. Never authorize via header alone or trust claimed clientInfo. |
| Tools and resources | input/output schema, structuredContent and text compatibility, distinguish protocol errors from tool error results, tool annotations as hints not permissions. Scoped resources/templates with opaque handles, authorized read/list, redacted ontology, deterministic pages. |
| MRTR and optional extensions | Multi-round-trip input-required/resume only when needed, bounded signed/opaque state bound to actor/scope/policy/purpose/expiry; explicit user confirmation is not device execution authority. Tasks extension for durable long investigations, auth each get/update/cancel as specified; subscription streams only if implemented; avoid deprecated roots/sampling/logging and legacy HTTP+SSE for new clients. MCP Apps optional sandboxed read-only visualization, no tokens/raw topology in app HTML or unapproved host fetch. EMA evaluate for enterprise IdP policy; no unsupported capabilities advertised. |
| OAuth | Protected Resource Metadata RFC 9728 and proper WWW-Authenticate, AS metadata RFC 8414/OIDC discovery, resource indicators RFC 8707, issuer/audience/signature/expiry/scopes, exact redirects/PKCE where applicable, RFC 9207 issuer validation, CIMD versus deprecated DCR per supported profile; issuer-bound credentials. Delegate to enterprise IdP, do not build new identity provider. No token passthrough; API keys explicit local legacy only. |
| Conformance | Requirement-ID matrix (MUST/SHOULD, applicability, evidence, gaps); pin official conformance tests and schemas plus independent Python/TypeScript client/server checks. Negative tests, two independent real clients, all declared capabilities; do not count skipped tests or self-client interoperability as certification. Publish client matrix, supported extensions and known gaps in UI/docs. |

[A2A v1.0](https://a2a-protocol.org/dev/blog/2026/03/12/a2a-protocol-ships-v10-production-ready-standard-for-agent-to-agent-communication/) released March 12; use pinned stable 1.0-series spec and [TCK/Inspector roadmap](https://a2a-protocol.org/v1.0.1/roadmap/) when implementing. [September roadmap](https://a2a-protocol.org/dev/roadmap/) describes 1.1 work, not an October compliance claim. A2A and MCP complement: agent-to-agent delegated investigations vs tools. Pilot one Agent Card skill for missing-prefix investigation, typed message/artifact, task lifecycle, get/list/cancel/stream according to declared binding, authenticated extended card if needed. No raw internal URLs or topology in public card; bind context/task to identity and tenant, reauthorize each access, no ambient delegation, webhooks disabled until signed and allowlisted. Reuse investigation store, not a competing agent runtime.

Framework matrix (acceptance targets, not compatibility claims): official Python + TypeScript MCP SDK (both directions); [OpenAI Agents SDK](https://openai.github.io/openai-agents-python/mcp/) (local client first, hosted tool path separate approved disclosure); LangGraph/LangChain MCP adapters; Google ADK (MCP and later A2A); [Microsoft Agent Framework](https://learn.microsoft.com/en-us/agent-framework/agents/tools/) (.NET/Python), then CrewAI/Semantic Kernel if demand. Pin compatible release versions, actual wire revision, auth, structured output, cancellation, cache isolation, negative cases. Framework wrappers must not elevate scope, and mock/local deterministic harness can qualify protocol without paid models. Provide minimal samples, OpenAPI fallback and private catalog; avoid public registry publication of enterprise endpoints.

Other design references: [OWASP Agentic Top 10 2026](https://genai.owasp.org/resource/owasp-top-10-for-agentic-applications-for-2026/), [Agent Control Standard, Sep 2026](https://genai.owasp.org/resource/agent-control-standard-acs/) for portable interception/control; [NIST AI Agent Standards Initiative](https://www.nist.gov/news-events/news/2026/02/announcing-ai-agent-standards-initiative-interoperable-and-secure) research not certification; [RFC 9700](https://www.rfc-editor.org/rfc/rfc9700.html), RFC 8693 token exchange, RFC 8705 mTLS, RFC 9449 DPoP, SPIFFE/SPIRE optional workload identity; [TM Forum IG1251C v2](https://www.tmforum.org/resources/standard/ig1251c-an-level-4-target-architecture-v2-0-0/) closed-loop service/resource governance, no claim of L4. ## 4. Identity, tenant and disclosure security

Create managed agent principals in existing auth/config/vault authority: owner human/team, tenant/environment, issuer+subject+client ID, workload identity, credential reference/expiry, allowed scopes/actions/destinations/purpose, trust level, status, policy revision. Distinguish service accounts from human delegated agents; delegation chain has explicit subject/actor, grant intersection, max depth/TTL and no privilege increase. Prefer short-lived access tokens; evaluate sender-constraining and token exchange with supported IdP. Never accept model-supplied tenant, role, clientInfo or trace metadata as authority. No global Admin grant for agent account. Rotate, revoke, expire, suspend, emergency kill switch; reauthorize before query, disclosure, task execution/retry/stream chunk and resource dereference; invalidate caches and cancel queued/in-flight work; bytes already disclosed cannot be revoked.

Enforce tenant from trusted inventory ownership and verified telemetry identity, not merely exporter IP or caller-provided label. Tenant/site/device/VRF/RD/service/signal/field/time-window/purpose attributes with explicit deny, intersections and policy revision. Shared PE/router, overlapping IPs/RDs, multi-tenant links and unmapped data need explicit ownership/relationship semantics. Device ownership never implies all VRFs or neighboring endpoints. Filter **before** joins, traversal, aggregation, search, vector retrieval, counts, sorting, cache, pagination and exports; fail closed when provenance cannot be established. Test graph edges, evidence handles, incident summaries, topology, routing journal, metrics, Parquet, embeddings, task state, feedback, schema, traces, UI/export and side channels (errors, counts, timings, cache hits). Strict mode today only denies unsupported access; prove real filtering or choose separate tenant instances/stores for high isolation. Do not migrate Ladybug or claim logical isolation suffices for regulated customers without measured threat/scale review.

Data classes: public/synthetic, internal operational, restricted infrastructure/customer, secrets/regulated personal data. Default deny secrets even to privileged external agents: passwords, tokens, keys, SNMP communities, raw auth/config credential material. Restrict management addresses, device names, routes/topology, ASN/RT/RD, policy/config, vulnerabilities, flow tuples, client MAC/user/SSID and incident/customer context by destination and purpose. Allow field allowlists/typed minimization, scoped pseudonyms (tenant/destination-keyed, stable within allowed scope), aggregate/coarsen, redact free text, deny or require approval; no raw payload capture by default. Aggregates can reveal hidden data: minimum cohort and differencing/cumulative query budgets where needed. Sensitive content classifiers augment deterministic allowlists, never sole gate. No automatic external fallback on outage.

Apply same disclosure gate before any external MCP response, provider prompt/prefetch/history, embedding call, enricher/MCP request, A2A artifact, export, SIEM/trace sink, notifications and UI payload preview. Inspect response shape and outgoing serialized bytes, including errors, metadata, URL/headers (not storing credentials). Outbound destination registry: endpoint, owner, tenant/purpose, approved region/provider/model, data class, contractual retention/training metadata (admin attestation not technical guarantee), allowed DNS/address ranges and TLS, vault credential ref, limits. Reject unregistered endpoints, redirects or DNS rebinding to private/metadata networks except explicit approved local service; cap bytes/time before parsing, validate schemas and no implicit credentials. Default local-only/deny external until policy configured. External hosts may forward content outside Bonsai; document boundary; never claim to monitor their hidden prompts, tools, token usage or subsequent disclosures without trusted instrumentation.

Prompt injection: malicious syslog, BGP/LLDP descriptions, configs, CMDB, tool metadata or response can be authenticated but untrusted instructions. Treat as data, separate typed evidence/control, no executable instructions in model output, no policy from natural language, allowlisted typed tool names and arguments, no untrusted URI following. Quarantine suspicious text, constrain output and broker, test indirect injection, tool poisoning, cross-agent confused deputy and cumulative extraction. Map threats to OWASP agentic risks (goal hijack/tool misuse/privilege abuse/supply chain/code execution/memory poisoning/insecure communication/cascades/human trust/rogue agents). Signed/pinned tool schemas and external manifest changes require review. No claim injection detector makes prompts safe.

## 5. Exchange ledger, observability and operator UI

Extend existing Audit/Investigations and UI-first config/fleet policy. A durable exchange record is separate from sampled traces; use existing protected storage/append-only audit facilities after review, bounded retention/compaction and optional external WORM/SIEM, not raw graph secrets or endless payload history. Metadata-only default. For each inbound and outbound attempt (including deny, error, retries, partial stream, canceled): exchange_id, timestamp, trace/span/parent/investigation/task IDs, direction, trusted principal/agent/delegator/tenant, client declared version (untrusted), protocol/operation/tool/schema revision, purpose, destination identity/region, effective scope and policy revision, authorization outcome/reason, class/field counts/redaction actions, original vs disclosed byte counts, result status, latency, query cost, evidence IDs/checkpoint, optional keyed digest of canonical redacted payload, delivery state (attempted/committed-to-wire/acknowledged/unknown), linked approvals. Never store secrets in URL/error/trace/baggage; no raw args/results in metrics labels. Trusted audit metadata must be protected from tenant users not entitled to it; trace IDs are not credentials. Provider usage/cost only if actually reported or clearly estimated; external model hidden costs unknown.

Record policy decision and durable egress intent **before** disclosure. If ledger unavailable/full, deny external disclosure; maintain local safe operation with explicit health alarm. Commit outcome after send; crash between send and receipt leaves unknown, not false delivered/undelivered, idempotent retries bounded. Test disk full, failed writes, restart, tamper, duplicate, clock skew and backpressure. Optional encrypted redacted payload sample (explicit tenant/admin approval, short TTL, separate role, access itself audited); default no prompt/response capture. Retention configurable by class/tenant, bounded bytes, purge incl. backups where possible, legal hold/export and deletion semantics; don't promise immediate backup purge or remote deletion. Cryptographic integrity/hash chaining with protected checkpoint/keys if required; don't label tamper-evident logs immutable without independent proof.

OpenTelemetry spans for MCP client/server, agent invocation, tool execution, policy/redaction, query, provider/inference/embedding and downstream adapter; correlate with W3C trace context, sanitize untrusted baggage and link across trust boundaries. Pin GenAI semconv version; record latency/errors/size/queue/quota/denial rates as bounded-cardinality metrics, per-tenant detail in ledger not labels. Keep ingest protection, rate limits by principal/tenant/tool/cost and cancellation; sample traces independently of complete security audit. Export via approved OTLP/SIEM without leaking content; UI shows missing trace/remote unknown clearly.

## 6. Deterministic autonomous operations

Start with read-only observe -> scope -> retrieve checkpointed evidence -> compute deterministic predicates -> explain/abstain -> propose next check -> independent verification -> operator decision. Evidence contract already in November 16 delta: immutable evidence IDs, source/view, time, freshness/completeness, provenance and query limits. Extend curated tools for domain questions, not huge raw Cypher: explain_missing_prefix, get_peer_timeline, get_evidence_coverage; later trace service/LSP, evaluate N-1, congestion/optics, wireless roam/AAA and blast radius (BN-024–027). Add explicit contrary evidence, confidence calibration outside model, evidence quality flags and reproducible proof object (predicate/version, input refs, result, limitations). A model may choose what to inspect but not change facts, mark incomplete evidence healthy or assert packet forwarding from graph topology. Compact summaries and lazy authorized dereference improve cost/accuracy; test against deterministic runbook and hidden independent oracle.

Durable incident-triggered investigation queue and subscriptions: explicit approved trigger policy, dedup/idempotency keys, per-tenant quotas, priority, deadline, gap/replay cursor, cancellation, bounded retries, cooldown and storm circuit breakers; event delivery is authorized and minimal, no arbitrary callbacks. Reuse existing incidents, event stream and persisted investigations; optional Tasks extension then A2A when benefit measured. External orchestrator can request scoped investigation and receive typed artifacts; no arbitrary remote instructions or agent-to-agent grant amplification. Replay policy/evidence/schema versions; never store private model chain-of-thought as requirement, record observable tool decisions and evidence.

Autonomy progression: A0 deterministic API/no model; A1 human-initiated diagnosis; A2 bounded incident-triggered read-only diagnosis and operator escalation; A3 lab-only simulation/proposal and independent verification with human approval. Live closed-loop actuation **out of scope**, separately authorized under BN-001/002/014 with preconditions, signed plan/assurance, lock/fencing, rollback, independently measured postconditions and kill switch. No tool, extension, delegated task or UI flag may enable device writes. TM Forum levels are scenario-specific; no level certification.

Evaluation: existing 44-scenario routing pack, held-out real labs with independent oracle, per-provider/framework/version, same evidence budgets, compare runbook/curated MCP/low-level and delegated A2A. Measure correct diagnosis/abstention, false supported claims, time-to-evidence, tool errors/repeats, bytes/tokens/cost per correct outcome, cross-scope canary leaks (zero), unauthorized actions (zero), revocation and cancellation SLO, audit completeness, p95/p99 latency and ingest lag, recovery. Include prompt injection, forged data, shared VRF, outages, malformed transport, concurrent agents, stale/gap, ambiguous ownership, conflicting data, budget and audit saturation. Set numerical latency/scale SLOs after baseline, not invented. Operational shadow pilot with real operators and no live writes before broader release.

## 7. Delivery and promotion gates

G0: reproduce source-confirmed boundaries with synthetic tests; strict agent isolation and protected auth storage dependency; disclosure policy, durable ledger and prefetch/callback/outbound negative tests before enabling any external tenant or hosted model. No change to existing operator compatibility default by this documentation.
G1: modern wire and one read-only missing-prefix tool end to end, legacy matrix, OAuth, typed contract and private discovery; independent official SDK clients/server and local tests.
G2: complete UI-first governance/exchange/trace and tenant-isolated evidence resources, quotas/revocation/cache/export/retention; browser and fail-closed fault acceptance.
G3: framework integrations, incident-triggered tasks, optional MCP Apps/EMA/A2A pilot with explicit benefit, hidden oracle, live lab and bounded soak with ingest, before shadow pilot.
G4: shadow operator evaluation and independent release decision; no live device execution. Gate order is dependency-based; work in small bounded slices, preserve existing secure-core review. Any implementation should reconcile current head, record exact SHA, tests/commands, failure/limits and evidence; no new deployment or paid calls authorized.

## 2. Practical feature comparison

M6C-2 must gate effective schema and encoding; investigate TARGET_DEFINED/heartbeat/suppress-redundant, prefix/target, updates-only **only with proved NOS support** |
| Connection transport | Per-target client and reconnection, target spec diff | TLS settings, gRPC keepalive and maximum receive size, one address goroutine, reconnect timer | Bonsai has authorized TLS/mTLS and explicit isolated-lab plaintext, but configurable gRPC transport budgets and jittered fleet recovery need acceptance |
| Discovery / compatibility | Capabilities and platform-dependent target options | Encoding validation; explicit nil empty prefix for a Huawei NE40 compatibility case | Bonsai retains rich Capabilities and RFC 8525 schema evidence (M6C-1). Test negotiated encoding and nonstandard prefix behavior; never silently infer support |
| Subscription truth | Lifecycle/response metrics and running/failed target statuses; per-subscription restart | Connected TCP/gRPC state; no Bonsai-style authority/sync evidence | Bonsai M5.2B tracks submitted vs synchronized, exact path receipt, session rank, provenance and withdrawal. **Preserve; do not regress to upstream connection-is-healthy semantics** |
| Reconnection and configuration | Cancellable retry with jitter, independent probe without config lock; targeted diff for conn vs subs vs outputs | Fixed configurable redial after stream exit; one goroutine per address | Bonsai has exponential reconnect but no jitter observed; integrate centralized desired/applied revisions, bounded retries and site-wide admission |

### Distinctive upstream procedures worth reusing

**gNMIc target manager** — [manager implementation](https://github.com/openconfig/gnmic/blob/3eca97f2cb77ebddd4d01839219da604f68a928f/pkg/collector/managers/targets/targets_manager.go) has explicit target states, cancellable retry, jittered `retryDelay`, a bounded Capabilities probe outside the target lock, and targeted connection/subscription/output changes. [Race-focused tests](https://github.com/openconfig/gnmic/blob/3eca97f2cb77ebddd4d01839219da604f68a928f/pkg/collector/managers/targets/targets_manager_subscribe_test.go) verify that a subscription re-applied while a target is down or starting does not orphan other subscriptions. In the reader loop the pipeline send is nonblocking: when full, gNMIc counts and logs a dropped SubscribeResponse. This trades downstream completeness for reader responsiveness; **never copy it without Bonsai gap/coverage invalidation**.

**gNMIc distribution** — [placement](https://github.com/openconfig/gnmic/blob/3eca97f2cb77ebddd4d01839219da604f68a928f/pkg/collector/managers/cluster/placement.go) prefers maximum available member quota and deterministic hash tie-break. [Dynamic config apply](https://github.com/openconfig/gnmic/blob/3eca97f2cb77ebddd4d01839219da604f68a928f/pkg/collector/api/server/apply.go) and [typed outputs](https://github.com/openconfig/gnmic/blob/3eca97f2cb77ebddd4d01839219da604f68a928f/pkg/outputs/output.go) separate target, subscription, processor and sink management. Bonsai should keep authenticated Core as the single control-plane authority and retain collector session fencing when adopting revisioned rollout or placement ideas; a distributed lock alone is not the existing trust contract.

**Telegraf gNMI input** — [configuration and request builder](https://github.com/influxdata/telegraf/blob/162e253e24306bb3f0304facb4704cb6177067cb/plugins/inputs/gnmi/gnmi.go) validates encodings, subscriptions, aliases, tag subscriptions and TLS; builds STREAM requests with `updates_only` and optional depth extension; avoids sending a completely empty gNMI Prefix for a known interoperability case. Its [subscriber loop](https://github.com/influxdata/telegraf/blob/162e253e24306bb3f0304facb4704cb6177067cb/plugins/inputs/gnmi/subscriber.go) has configurable keepalive/message size and a fixed redial interval, but may use insecure transport when TLS is absent. This is a feature reference, **not** permission to relax Bonsai's approved security modes or infer health from TCP connectivity.

**Telegraf decoder/metadata** — [handler](https://github.com/influxdata/telegraf/blob/162e253e24306bb3f0304facb4704cb6177067cb/plugins/common/gnmi/handler.go), [path utility](https://github.com/influxdata/telegraf/blob/162e253e24306bb3f0304facb4704cb6177067cb/plugins/common/gnmi/path.go) and [tag store](https://github.com/influxdata/telegraf/blob/162e253e24306bb3f0304facb4704cb6177067cb/plugins/common/gnmi/tag_store.go) merge prefix/update, derive keyed tags, process tag subscriptions before fields, support aliases/field grouping and optionally parse a Juniper header extension. These transformations are helpful for metrics but can strip information, change names or increase cardinality; preserve the original structured gNMI path/value/source and trace a separate versioned normalized projection.

**Vendor dial-out is heterogeneous** — [Telegraf gNMI listener](https://github.com/influxdata/telegraf/blob/162e253e24306bb3f0304facb4704cb6177067cb/plugins/inputs/gnmi_listener/gnmi_listener.go) only registers a Nokia protocol implementation, while [Cisco MDT input](https://github.com/influxdata/telegraf/blob/162e253e24306bb3f0304facb4704cb6177067cb/plugins/inputs/cisco_telemetry_mdt/README.md) consumes Cisco GPB-KV over its own TCP/gRPC delivery. Neither is proof that an arbitrary device supports a general-purpose gNMI dial-out Subscribe service. Phase separate passive transport, schema decode, authenticated source binding, path normalization and graph authority.

## 3. Bonsai code findings (static at pinned SHA)

### C1 / P1 performance + durability investigation — per-record sync and per-batch entire-backlog rewrite

[`src/ingest.rs`](https://github.com/g-arjuna/bonsai/blob/b591a7f12abb1a26068f7b41e38fa436e9ce0132/src/ingest.rs): `CollectorQueueInner::append` opens the data file, appends protobuf framing, and calls `sync_data()` for **every** event. `next_batch` calls `enforce_limits`, whose `unacked_records` decodes/scans all remaining records. `ack` calls `compact_reclaim_acked` after a batch, reconstructing the unacked tail into a temporary file, syncing and renaming. `stats` also scans. Size-pressure eviction uses `Vec::remove(0)` repeatedly; that is O(n) per removal. These are concrete source-level complexity costs, not a measured performance regression.

Design a bounded segmented append-only WAL with amortized sequential append, batched/group commit at a documented durability boundary, checkpointed offsets, segment-only garbage collection, byte/age quotas and crash-safe recovery. Do **not** remove fsync without defining whether an RPC acknowledgment promises volatile enqueue, collector WAL persistence, Core durable ingestion, or graph projection. The current `accepted+rejected==submitted` check in `drain_queue_to_core` is sound accounting but does **not** prove graph projection or historical archive durability. Prove ACK replay on Core crash and independent dropped/expired/rejected attribution.

### C2 / P0 evidence integrity — bus pressure and loss attribution

[`src/ingest.rs`](https://github.com/g-arjuna/bonsai/blob/b591a7f12abb1a26068f7b41e38fa436e9ce0132/src/ingest.rs) registers `collector_forwarder` as an MPSC subscriber with 4,096 entries and `DropNewest`. [`src/event_bus.rs`](https://github.com/g-arjuna/bonsai/blob/b591a7f12abb1a26068f7b41e38fa436e9ce0132/src/event_bus.rs) records subscriber drop counters and `PublishOutcome::Overloaded` at the router, but `subscriber.rs` publishes gNMI updates without checking that returned outcome. Explicit loss metrics are useful, yet drop recognition is not equivalent to an authoritative coverage-gap transition or durable collection. **Investigate via red test** whether lifecycle-critical state changes, deletes and initial snapshot records can be lost while UI still reports coverage as valid.

Define priority classes, per-path/target byte ceilings and a deterministic gap/freshness invalidation contract; do not block the gRPC receive loop indefinitely or introduce unlimited in-memory buffers. Coverage path evidence must not be mistaken for persisted history. Preserve the rule that current-session telemetry bypasses lossy counter summarization.

### C3 / P1 decoding correctness — no fabricated nulls or coerced malformed JSON

[`src/subscriber.rs` `typed_value_to_json`](https://github.com/g-arjuna/bonsai/blob/b591a7f12abb1a26068f7b41e38fa436e9ce0132/src/subscriber.rs#L2076) maps unhandled variants to JSON null; malformed `JsonVal`/`JsonIetfVal` is converted to lossy UTF-8 string. The currently handled cases cover some JSON and scalar types, **not every gNMI TypedValue variant**. This can erase type distinctions for decimal, leaf list, bytes, proto/mixed payloads; it may conceal malformed payloads as apparently valid readings. Introduce a typed, bounded decode result with explicit `unsupported` / `malformed` / `out_of_budget` outcomes, preserve original bytes and protobuf for replay/evidence under defined limits, then derive JSON/metric fields only from validated values and active device-effective YANG. Preserve unsigned 64-bit counters and decimal precision; never coerce missing or invalid to zero/null with a healthy quality flag.

### C4 / P1 negotiation and automatic selection — evidence versus assumption

[`src/subscriber.rs` `ModelCapabilities::from_response`](https://github.com/g-arjuna/bonsai/blob/b591a7f12abb1a26068f7b41e38fa436e9ce0132/src/subscriber.rs#L1415) chooses JSON_IETF if advertised, else JSON even without an explicit advertised JSON match. The failed Capabilities path uses vendor-hint defaults and can produce broad automatic subscriptions. Strict **explicit/disabled acquisition already fails closed**; retain it. Feed M6C-1's device-effective module/feature/namespace evidence into M6C-2 before activating broader automatic plans. Distinguish `advertised`, `probed`, `submitted`, `synchronized`, `observed` and `projected`; reject/mark unknown when an encoding or path has not been justified. Require negative tests where a device advertises PROTO only, no supported encoding, Capabilities timeout or a changed module-set.

### C5 / P1 fleet availability — no jitter and missing transport budget audit

[`src/subscriber.rs`](https://github.com/g-arjuna/bonsai/blob/b591a7f12abb1a26068f7b41e38fa436e9ce0132/src/subscriber.rs) uses exponential backoff 5–60 seconds and resets after a sufficiently long stream, but sleeps the exact duration without fleet jitter. Connection timeout is 30 seconds. Per-target configured keepalive, max decoded response bytes, concurrent active session/admission and initial-snapshot cost budgets were not established by this inspection. Borrow gNMIc's cancellation/jitter/retry-without-lock pattern and Telegraf's explicit gRPC size/keepalive controls, but retain authenticated assignment leases, lifecycle states and Core-owned revision authority. Test 100/1,000 simulated devices starting together, dropped network, slow Capabilities and policy withdrawal.

### C6 / P1 path and vendor schema fidelity — structured source first

Bonsai's [`src/gnmi_path.rs`](https://github.com/g-arjuna/bonsai/blob/b591a7f12abb1a26068f7b41e38fa436e9ce0132/src/gnmi_path.rs) already has bracket-aware canonical structured paths. In the subscriber, `path_to_string` formats keyed segments without escaping key content, while downstream classification still consumes a string path; this must be tested against keys containing slash, brackets, equals, namespace prefix and multi-key list identity. Preserve the structured `gnmi.Path` as authority; aliases/tag projections must not make two distinct canonical paths collide. Validate prefixes, origin/target, requested-vs-wire path and first-namespace normalization only with per-NOS fixtures. The reference Telegraf alias approach is for presentation, not canonical identity.

### C7 / P1 operator control and outputs — extend existing systems

[`src/output/traits.rs`](https://github.com/g-arjuna/bonsai/blob/b591a7f12abb1a26068f7b41e38fa436e9ce0132/src/output/traits.rs) defines adapter isolation/scope, and [`src/output/mod.rs`](https://github.com/g-arjuna/bonsai/blob/b591a7f12abb1a26068f7b41e38fa436e9ce0132/src/output/mod.rs) has multiple concrete output adapters. The [19 November UI/fleet audit](UI_FIRST_CONFIGURATION_FLEET_REVIEW_2026-11-19.md) already documents that API saves may not reconcile running adapters and that `syslog` is accepted as a config type without a matching builder. Do not add another plug-in API; add versioned typed desired/applied/verified configuration and supervised per-sink cancel/restart/health, scoped queue and true delivery policy to existing infrastructure. Changes through Core UI must supersede stale collector config, not require manual TOML edits after enrollment.

## 4. Recommended Rust-native design

Use a **single controlled data path, separate durable evidence and derived metric projections**:

1. **Plan:** Core inventory + M6C-1 schema evidence + versioned intent → immutable plan fingerprint, per-NOS verified encoding/path features and budget estimate. No collection when disabled, invalid or unauthorized. Expose preview and precise rejection causes to UI.
2. **Assign:** existing authenticated CollectorManager authority epoch, assignment generation, withdrawal acknowledgment, session execution generation; add constrained fleet/site admission and rolling/canary activation, not competing leader election.
3. **Acquire:** one supervised Tokio task per target (or measured isolation group), tonic/prost with configurable bounded message/stream, deadlines and keepalive. Cancellation-safe jittered reconnect and no locks across await. Preserve original protobuf and device/collector clock provenance.
4. **Decode:** bounded, schema-aware typed outcomes; structured prefix + update/delete path; optional vendor translators with separate source/protocol IDs and allowlisted extensions; immutable raw evidence plus independently versioned normalized value. Avoid per-update JSON allocations until a consumer actually needs JSON, and validate whether a zero-copy/`Bytes` change helps before adopting it.
5. **Classify:** distinguish critical state transitions, delete, sync/lifecycle, counters, unknown schema and forensic payload. Preserve path+origin+target+keys+time+identity and original-source binding. Sampling/aggregation may affect counters only under declared policy; absence, zero and unknown are different.
6. **Buffer:** bounded by **bytes and events** per collector/target/priority with explicit overflow action, drop reason and impacted scope/coverage gap. Reserve capacity for critical transitions, control/lifecycle traffic and bounded operator reads. Do not block all receivers behind a bad output.
7. **Persist:** append-only segmented spool with indexed offsets and an explicit durability/ACK contract; fsync grouped by policy after recording loss window. Maintain high/low watermarks, OS disk free guard, max age, replay, dedup/sequence and replay-safe admission. Use `spawn_blocking` for unavoidable blocking fsync if measured; benchmark disk/cache/CPU first.
8. **Fan out:** Core ingest once, then independent typed sink queues/ack/retry with failure isolation and tenant/environment scope. Graph authority derives from validated source trust; a Telegraf-style processor or Prometheus export must never promote a provisional fact into a canonical device state.
9. **Observe:** per-target statuses (configured/connecting/submitted/synchronized/observed/stale/rejected), queue depth in bytes/records, durable backlog age, receive/decode/persist/forward/export lag, drops, retries, schema version, CPU/RSS, stream rate, last timestamps and effective settings through UI/API/MCP.

**Performance discipline:** compare (A) current Bonsai, (B) one optimized Rust candidate and, as *reference only*, (C) gNMIc and Telegraf on equivalent synthetic gNMI workloads. Pin versions, encoding, payload size, path fanout, generated event time, persistence/fsync policy, destination and machine; report CPU-seconds/1M verified observations, peak RSS, p50/p95/p99 receive-to-accepted and receive-to-committed lag, EPS, durable write amplification, reconnect success and bytes/event. Report startup/catch-up after a 10-minute Core disconnect and 100/1,000-device synchronized restart; no arbitrary headline EPS or claims of losslessness. Use representative interface counters, keyed list updates, ON_CHANGE, deletes, large protobuf/JSON_IETF values and mixed vendor profiles. Benchmark under queue saturation, disk-full, partial write, Core rejection, checksum error and CollectorManager withdrawal. Observe whether async channel contention, cloning, protobuf→JSON conversion or fsync is the actual bottleneck before optimizing.

## 6. Review/implementation guardrails

- Work from [AGENTS.md](../../AGENTS.md), canonical backlog and current `docs/STATUS.md`; preserve existing dirty worktrees, independent builds, BN-009 soak evidence and dev host resource caps. No broad dependency upgrades, force push, destructive cleanup, production Set/gRIBI writes or unaudited credentials.
- At each slice kickoff, diff **current** Rust against this pinned baseline; first write the failing integration fixture or benchmark reproducer. Classify source-static suspicion versus reproduced bug. Do not silently weaken existing M5.1/M5.2B/M6 gates.
- Capture both wire request (including exact SubscribeList) and source observation with collector, session, schema revision, origin, target, keys, prefix, timestamp, deletes and lifecycle event. Report actual CLI commands, exit codes, run SHA, memory/disk statistics and evidence; no skipped tests as passed.
- Telegraf and gNMIc source are *inspiration and independent oracles*. Reimplement procedures idiomatically; if copying code is proposed, separately review license, required notices and attribution under the repository's licensing policy.
- Preserve clean conceptual boundaries: **device protocol/transport**, **collector authority & durability**, **normalization**, **Core projection**, **metric persistence/output**, **operator UI**. Avoid adding another authoritative config store, mandatory broker, duplicate graph writer or false green dashboard.
- At closeout, update **only** BONSAI_BACKLOG.md and docs/STATUS.md as warranted by executed evidence, link the result, use a bounded PR/gate and clean only worktrees/branches created for that slice. Documentation review is not proof of implementation.

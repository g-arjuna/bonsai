## Decision and deployment

Keep Rust Core/collector, authenticated gRPC, Ladybug semantic graph, canonical routing service/journals, SQLite control store (optional PostgreSQL under BN-029), and Arrow/Parquet history. In-process bus remains useful for best-effort notifications; it is not a durable receipt. Separate receipt, processing and visibility. Broker-free standalone remains the baseline; distributed enterprise can use external metrics/log/flow stores; global installations may qualify region-local replicated transport and separately scaled consumers, never implicit active-active graph writers. Preserve BN-021 identity/assignment/epoch fencing and BN-024 typed fact ABI; external components never confer authoritative identity.

Target: verified collector capture -> class-aware bounded durable ingress -> independent checkpointed semantic projection, correlation, metrics/flow/history, archive and ML consumers -> authorized time-aware evidence API -> UI/MCP. Numeric aggregation is explicit; preserve critical transitions, deletes, gaps, audit, routing authority. Use canonical routing journals rather than competing routing ownership. Do not build a general distributed broker, TSDB, search cluster or SQL streaming platform.

## Implementation intake and acceptance (existing owners)

**A — BN-008/009/019/021/023, durability first (P1 intake; existing critical gates unchanged).** Study Vector and canonical rbmp journals. Segmented checksummed append, generation-bound durable ack/checkpoint, batched fsync, hard append-time byte/age budgets and reserved critical capacity, stable observation identity and independent per-consumer committed offsets. No silent loss; report scoped gaps. Test kill points before/after fsync, ack and graph commit, compaction, disk full, corrupted offsets, sink failure, WAN outage, stale assignment replay, live+catchup, no duplicate effects. Separate UDP pre-ingress loss from durable admission. Broker PoC Kafka vs JetStream vs direct only after baseline proof and measured RPO/throughput need; scoped ACLs, ordering, retention, rebalance/redelivery, host loss, rollback; no shared/wide-area authority. 

**B — BN-024/025-02/009/019, deterministic stateful processing (P1 intake after durable receipt/typed facts).** Evolve existing correlation buffer and summarizer, not another parallel pipeline. Explicit event/receive times, source clock quality, source/session/sequence and acquisition coverage, deterministic ordering/tie-breaks, per-scope/source watermarks, idle/disconnected source gaps, late event correction with versioned incident evidence, keyed state limits/TTL, timer and checkpoint recovery. Event-time progress is not evidence completeness. Temporal joins use as-of topology/config/routing/identity, not today's graph. Tests: shuffled and duplicated input, late optical/BMP/syslog/flow, same IP across scopes/VRFs, flaps, tombstones, missing source, clock skew, replay after revoke, restart mid-window, independently expected results and bounded memory. Never infer causality solely from temporal ordering. No arbitrary SQL stream engine.

**C — BN-008/013/016/024-20/025-09/019, historical analytics (P1 intake).** Typed Arrow/Parquet schema, immutable finalized manifest, event time/units/quality/source offsets, bounded row groups/partitions/compaction and safe retention. DataFusion vs existing DuckDB baseline on same corpus: range scans, percentiles, flow group-by, time-window joins, as-of topology and ML export; correctness, cold/warm latency, bytes scanned, peak RSS, CPU, concurrency and ingestion impact, build/link cost. Authorized evidence interface with time/scope/row/byte/work quotas, coverage, freshness, original references and missing/expired/partial states. No raw unrestricted SQL. Optional ClickHouse for high-volume flow/log analytics; validate ingestion/dedup/TTL and receiver query, not a default store.

**D — BN-008/016/021/019/023, reliable outputs (existing P1 intake).** Fix Prometheus pre-send buffer loss, bounded batches/retry, typed series identity/ordering/reset/wrap/cardinality, appropriate pre-summary placement. Fix Elastic/HEC pre-ack dedup and timestamp-only cursor; per-item status, stable IDs, contiguous commit progress, retryable/permanent failures and scoped gaps. Actual receiver query and restart/outage/mixed-success tests. Reuse output registry/vault/UI; no new generic adapter framework.

**E — BN-024-16/17/20, incremental reasoning (P2 research).** Timely/Differential PoC over bounded scoped graph facts, compare full recompute on edge add/remove, route withdrawal, ECMP, cycles and incomplete graph. Exact parity, retractions, memory, restart and latency under churn; no authoritative mutations or default dependency.

**F — BN-028/013/030, embedded evidence search (P2 research).** Compare Tantivy with existing search and external SIEM; deterministic document/chunk IDs, version/time/source references, scope isolation before retrieval, redaction, tombstone/retention/incident pins, index rebuild and query budgets. Tests cross-scope denial and stale/deleted content not returned; search result is not truth or authority.

**G — BN-029/030/019, operator experience and sustainability (P1 intake).** Core UI/API managed per-class delivery/retention/aggregation/sink policy and desired/applied revisions. Show received/durably accepted/committed/projected counts separately, age/bytes/watermarks/gaps, per-consumer retry/checkpoint and destination health, lag vs availability, authorized audited replay/dry run, coverage and resource limits. Browser tests with degraded sink and collector restart; no config-file authority or misleading green status. Every new dependency: pinned revision/license/SBOM, duplicate Arrow versions, MSRV/platform, clean/incremental compile time, peak linker RSS, binary/image size, rollback and security review. Measure representative mixed gNMI/BMP/flow/syslog/OTLP workloads and usable retained coverage; no extrapolated product claims.

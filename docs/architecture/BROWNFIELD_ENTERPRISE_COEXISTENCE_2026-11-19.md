## Decision

Bonsai should work as an additive intelligence layer alongside existing enterprise infrastructure, not require migration to a Bonsai-owned monitoring or source-of-truth stack. It owns observed protocol state, canonical evidence, deterministic diagnostics and governed agent access; external systems retain their authority over intended infrastructure, historical samples/logs and change tickets. Deployment should start with the smallest useful scope and expand without a forklift replacement.

| Existing enterprise authority | Bonsai integration and boundary |
|---|---|
| Infrahub, NetBox, Nautobot | Approved intended topology, assets, IPAM, services and policy intent; retain source IDs, revision/branch and field provenance. Not proof of live connectivity. |
| ServiceNow / other CMDB and ITSM | CI/service ownership and approved change references; retain current integration and change assurance, no duplicate ticket authority. |
| Prometheus, Thanos, VictoriaMetrics, Mimir, InfluxDB | Existing metrics/history via scoped read API; optional normalized export if Bonsai owns collection for a signal. No default backfill or permanent local TSDB. |
| Loki, Splunk, Elastic / existing SIEM | Bounded read-only event evidence via typed templates, selected event ingest where authorized; separate from existing detection exporters. |
| Grafana | Deep links to authorized source dashboards and optional provisionable Bonsai dashboards for existing Grafana; Bonsai UI remains control plane. No automatic dashboard or alert modification. |
| gNMIc, Telegraf, Grafana Alloy, OTel Collector, existing SNMP/syslog relays | Optional approved telemetry handoff or query-only reuse; do not force duplicate device sessions or pretend generic metrics provide BMP/RIB fidelity. |
| External orchestration/AI frameworks | Consume Bonsai deterministic tools via AG-01–11, optionally alongside their own Grafana/Infrahub tools. No direct cross-system token passthrough or authority transfer. |

## 1. Infrahub as a first-class intended-state connector

Upstream [overview](https://docs.infrahub.app/overview), [GraphQL](https://docs.infrahub.app/development-resources/graphql/overview), [schema concepts](https://docs.infrahub.app/overview/concepts), [branches](https://docs.infrahub.app/branches/overview), [branch awareness](https://docs.infrahub.app/schema/branch-awareness) and [webhooks](https://docs.infrahub.app/webhooks/overview) establish flexible user-defined schemas, branch-scoped GraphQL, lineage and event integration. There is no universal enterprise object schema to hardcode.

Read-only GraphQL connector through existing enrichment/onboarding registry, with versioned mapping profiles for devices/interfaces/addresses/sites/cables/VRFs/services/intent attributes; schema fingerprint, typed mapping preview and incompatibility diagnostics. Use instance + immutable object ID plus branch/revision metadata; canonical identity is separately verified, never inferred from address alone. Default branch only for intended production state, explicit branch selection for candidate change simulation; branch-agnostic/branch-local fields preserved according to upstream semantics. Record source revision/snapshot/time and provenance without claiming cross-system atomicity. Initial bounded paginated sync and periodic reconciliation; optional verified webhook as a hint to refetch authoritative object, not trusted direct writes. Idempotency, replay, out-of-order events, deleted objects/tombstones, missed webhook/full resync, schema change and rate limit; incomplete page never causes mass removal. Import preview must not activate subscribers, assign credentials or overwrite observed topology. Link proposed-change ID/artifact hash to BN-014 baseline/candidate assurance; no mutation or automatic merge. Test two actual schema profiles, two branches and conflicting NetBox/CMDB/observed data.

## 2. Collection ownership and deployment profiles

A Core-managed source ownership matrix per tenant/site/device/signal/protocol defines who collects, who retains and which evidence is authoritative. Three supported target profiles: standalone (no external systems), overlay (read existing SoT/metrics/logs + selected Bonsai native routing/telemetry), hybrid (Bonsai collectors for missing signals and optional exports to enterprise history). External connector unavailable does not disable independent Bonsai collection or convert missing data to healthy. Existing device telemetry subscriptions continue unchanged until an authorized cutover.

Inventory imported from SoT is not permission to collect. Preview existing acquisition coverage, per-device session budgets and signal resolution. For handoff, qualify supported existing OTLP receiver or approved event/metric feed with producer identity and child-subject authorization (BN-021/027), and retain source/exporter timestamps and quality. A trusted gateway is not proof of device identity. Preserve original collection method, sampling, counter resets, scrape/aggregation windows; differentiate native observation, external normalized sample, aggregate and unknown. Dedup by canonical observation identity or explicit source ownership, never collapse distinct observations just because timestamp/value matches. Test parallel run, overlap, duplicate exporter, migration/rollback, late data, independent sensor sources and outage. Avoid assuming Telegraf/gNMIc can replace native BMP lifecycle. Provide deployment recipes with least privilege, exact supported version and networking/firewall guidance, no bundled enterprise systems by default.

## 3. Federated historical evidence, not data replication

Use existing TSDB API and shared evidence ABI to register tenant-scoped source instances and mapping descriptors: external label schema -> canonical device/interface/signal identity, metric units/type/reset/resolution, query template/version, source timezone/clock, auth and retention capability. Query only bounded instant/range summaries and selected time windows; avoid unbounded PromQL/Flux/LogQL from LLMs. Enforce authorization before backend query and after result; source-side tenant/label filters cannot be overridden by user strings. Validate parser/AST or fixed parameterized templates, exact identity (not regex prefix), normalized timestamps and range/step/sample/series/byte/time/concurrency budget. Credential resolution failure denies. Return source warnings, partial/expired/missing data and checkpoint/coverage rather than fabricated zeros. Record query hash, actual time range, resolution, source version and authorized result reference; bounded cache/evidence pin policy per PR #35. No blanket historic import.

Loki uses tenant header and external authentication, not a tenant header as identity ([authentication](https://grafana.com/docs/loki/latest/operations/authentication/), [multi-tenancy](https://grafana.com/docs/loki/latest/operations/multi-tenancy/), [HTTP API](https://grafana.com/docs/loki/latest/reference/loki-http-api/)). Resolve tenant header server-side from approved binding; no multi-tenant header composition or caller override. Scope log selectors, parse/normalize selected syslog evidence, preserve sender/receipt time and original source reference. Redact before disclosure, no arbitrary regex/LogQL/SPL or full text download. Extend existing selective SIEM broker, not another log store.

Prometheus-compatible range/instant read and Remote Write are separate capabilities ([HTTP API](https://prometheus.io/docs/prometheus/latest/querying/api/), [Remote Write tuning](https://prometheus.io/docs/practices/remote_write/)). Backend differences (partial response, tenant enforcement, histograms, dedup, retention) explicitly qualified. Grafana Alloy can receive syslog and forward it to Loki ([Alloy syslog](https://grafana.com/docs/alloy/latest/monitor/monitor-syslog-messages/)); prefer existing relay where approved over duplicating history. Do not assume any backend has infinite durable retries.

## 4. Shared workflows and UI

Extend Integration/Settings/Onboarding/Investigations, not another UI. Connection inventory shows type, approved destination/tenant, scopes, read vs export capabilities, version, mapping revision, health, freshness/last successful sync, effective vs desired configuration, errors/gaps, rate/quota/backpressure, source coverage and conflict review. All controls central, secret references write-only, no hidden file override. Show canonical asset + external IDs, intended/observed/validated comparison and source-specific time. Provide authorized deep links to source object, Grafana dashboard/time window, log/metric evidence and change request; generate from approved endpoint/template, no embedded tokens or arbitrary redirects; upstream RBAC remains. Optional curated Grafana dashboards and evidence/incident export are read-only artifacts or separately scoped notification writes, not device changes. [Grafana MCP](https://grafana.com/docs/grafana/latest/ai-tools/mcp/) includes tools that can modify dashboards and alerts; only read subset allowed for Bonsai evidence use. Cross-tool correlations use canonical scoped IDs and checkpointed evidence, not arbitrary tool output joins by hostname.

## 5. Acceptance and comparative benchmark

Start one representative real local Infrahub + Prometheus-compatible + Loki lab (version-pinned, synthetic or authorized lab data), existing Bonsai native BMP/gNMI and an external agent client. No paid systems or models required. A minimal overlay deployment must work without Bonsai collecting every metric. Measure both with and without external integrations.

Reproduce screenshot-style baseline: scheduled early-warning PromQL/LogQL + intended/observed dependency queries + ranking, same input traces and retention, matched query budgets and independent hidden oracle. Compare baseline vs Bonsai deterministic evidence workflow without model first; then same model/framework only if authorized. Include degrading link with corroborating optics/errors, rising CRC from unrelated cause, counter reset, stale/unavailable metrics, branch-only planned cable, redundant vs single-homed service, routing withdrawal, conflicting CMDB, overlapping tenant IP and duplicate acquisition. Measure lead time at matched false alarms, correct diagnosis/abstention, affected-service accuracy, evidence bytes/tool calls, runtime resource costs, device session count, deploy/operator effort, storage duplication and policy denial correctness. No prediction superiority or calibrated probability claim absent independent held-out outcome; BN-010/012 own ML qualification. Test restart, disconnect, expired credentials, webhook replay, partial query, source schema/label change, tenant leaks, denied direct API and egress audit failure. No secret or cross-tenant canaries disclosed. Preserve no-connector functionality and existing secure collection.

Promotion order: B1 authority and mapping/deployment contract; B2 Infrahub + hardened historical reads; B3 governed UI and hybrid handoff; B4 one end-to-end brownfield pilot and benchmark. G0 identity/disclosure/retention dependencies from PRs #35–37 required before external tenant use. Record actual versions, source revision, commands and results; no implementation or operational release claimed in this document.

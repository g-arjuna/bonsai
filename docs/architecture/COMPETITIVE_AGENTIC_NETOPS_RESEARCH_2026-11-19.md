## 1. Product direction and competitive reference points

Bonsai should be a self-contained, evidence-driven network operations product *and* an open agent-facing intelligence service. It should provide useful NOC outcomes with the LLM disconnected. Do not compete on proprietary model count, connector count or generic log storage. First win a narrow, real operational use case: a multi-protocol routing incident, independently evidenced impact, an operator-ready incident workspace, safe proposal and verified recovery. Extend across SP, fabric and campus profiles only after each is independently accepted.

## 3. Deterministic intelligence service: alarm, episode and causal chain

Distinguish **observation** (immutable raw/normalized evidence), **signal** (derived metric/log/state deviation), **alarm** (state of a resource over an interval), **episode** (candidate related event set), **incident** (durable operator lifecycle), **hypothesis** (ranked explanation), **verified claim** (predicate and evidence support within declared fidelity), **action** and **verification**. Reuse existing DetectionEvent, StateChangeEvent, Incident, investigation, playbook and approval data after schema audit; add minimal typed extensions rather than duplicate stores. RFC 8632 alarm state model (resource/type/qualifier, raise/change/clear and operator state/shelving) is a useful northbound mapping; RFC 8345 layered topology/termination points/supporting relationships and RFC 9232 telemetry taxonomy guide evidence types. Do not claim YANG interface compliance unless implemented/tested.

Event time vs receipt, source epoch, monotonic sequence when available, watermarks/skew, quality, active vs cleared, distinct raw identity, source instance/scope and canonical subject. Separate maintenance/shelve/ack/suppress from actual resolution. Durable incident ID independent of chosen root; membership revision, split/merge lineage, replay/correction, dedup after durable ack, restart, late event, source gap and retention pins. Never discard raw critical events just because they are correlated; ensure independent faults remain visible.

Candidate episode retrieval is bounded by scope, time and resource locality. Combine typed topology dependencies (not only degree), event direction, layer semantics, time uncertainty and evidence quality; pairwise temporal similarity and co-fire are only candidate features. Build a versioned, extensible protocol predicate registry: e.g. interface oper transition -> observed adjacency loss on same interface/session -> observed RIB/LFIB change for affected scoped route -> independent service probe or model-based possible impact. Each edge carries cause candidate, effect, resource/layer, interval, rule/model version, supporting and contrary refs, missing conditions, reason and state observed/corroborated/inferred/rejected/unknown. Bidirectional dependencies and feedback may produce cycles; represent bounded temporal event DAG or explicit ambiguous cyclic group, not fabricated ordering. Test multiple plausible roots, independent faults, common causes, counterexample and clock skew; never assert config change caused failure simply because it preceded it. Root can be unknown/multiple; display hypotheses and required next measurement. Stable ordering and canonical serialization for same checkpoint/policy/rule/model/input; deterministic reproducibility is not epistemic truth.

Blast radius: potential topology neighbors, modeled dependent services/routes/LSPs, measured affected SLO/service, unaffected with actual alternative path/probe, unknown separated. Account for redundancy, ECMP, backup LSP and shared-risk group, planned vs installed vs active path, partial observability and observed service map at event time. Incident priority from observed service severity, business criticality, duration, degradation, redundancy risk, coverage and confidence, explainable components and operator overrides; not number of alarms or graph centrality alone.

MVP scenario: deliberate isolated lab interface-down and separate simultaneous unrelated fault; OSPF/BFD/BGP/MPLS evidence only where qualified profile exists; track state/route changes, service endpoint checks; if only BGP available start missing-prefix/peer-down and independent ping from authorized lab endpoints. Compare old heuristic and new typed predicates, require no supported false uplink/config assertion, all raw event refs and repeatable outcome. Grow into optical degradation vs overload, policy withdrawal vs transport, partial EOR, convergence, multiple faults, harmless change, service redundancy, wireless roam/auth and fabric PFC. No production fault injection.

## 4. Signal intelligence and ML roadmap

- Normalization profiles from BN-024 and BF, source schema registry, typed event taxonomy with actual interface/neighbor/VRF/queue/radio/service IDs, canonical units, normalized dimensions and raw references. UI coverage/data-steward queue for failed mappings, inconsistent identities, clock skew, unseen schemas and source quality; correction staged/replayed, never autonomous ownership overwrite.
- WP6.5A template dedup and semantic embedding remain retrieval aids; test streaming template mining against Drain/approved vendor parsers, variable extraction (resource, error code, peer), template drift/novelty, frequency burst, sequence motifs and maintenance context; distinguish repeated event from new event. Never suppress critical state transition based on text similarity. Keep cost/bounded cardinality and embedding provider disclosure gates.
- Adaptive numeric baselines: seasonal median/MAD, EWMA/change-point, robust quantiles and workload cohorts, maintenance windows, counter reset/unknown masks, cold start, event drift, false-alert budgets, profile-specific thresholds, interpretable deviation and seasonality. Evaluate statistical fallback before self-supervised or per-series models; bounded models/job schedule and versioned calibration. No retraining every 30 minutes by imitation.
- Causal ranking: deterministic typed graph predicates and temporal/structural constrained candidate ranking first, graph-free/time-only/co-fire/centrality baselines, then GATv2/GRU and a separate supervised root localization/edge ranking head with typed relations and propagation labels, calibrated uncertainty and abstain. Compare no topology/no temporal/edge ablations, held-out topologies/vendor/fault families, multiple roots, hidden tests, clock/coverage degradation. Attention maps are model attribution, not proof. Validate causal direction via controlled interventions/independent measurements; no online auto-learning from thumbs-up or unverified tickets.
- Prediction is separate from detection and RCA. Define target fault, forecast horizon, actual event label and decision cost; lead time at fixed false alerts/device-day, precision/recall, PR-AUC, calibration, missed events and interval coverage; capacity forecast error and N-1 scenarios. RouteNet-Fermi as optional learned performance-model challenger for delay/jitter/loss given paths, traffic and queues, not RCA or exact forwarding. Train only on versioned authorized datasets, chronologically split by incident/site/topology, mask gaps, avoid future leakage. Register model/feature/calibration/dataset/lineage/license, shadow/canary/promotion/rollback, drift and fallback; no model can grant device changes.

## 5. Network DVR and assurance

Extend BN-024 temporal checkpoints, routing history and PR #35 retention: checkpoint + bounded deltas/segments, source-specific watermarks, actual event time and receipt time, clock quality, lifecycle tombstones/epochs, old topology and configuration snapshots. Query incident as-of and compare before/during/after, stable playback cursor, coverage/expiry/partial state explicitly shown; never reconstruct historical graph by reading today's edges. Lazy fetch metric/log windows via BF; preserve immutable evidence pins and source refs. Measure snapshot/delta size and seek latency; sparse checkpoints and bounded caching, no indefinite full graph snapshots. UI scrub/play/pause, time-aligned plots, layer toggles, path diff and causal edge drilldown; test historical failover, late corrections and restart. Replay determinism across same revision vs new algorithm rerun explicitly distinguished.

Independent assurance catalogue: typed intent check (reachability, isolation, required waypoint, forbidden path, prefix retention, redundancy, utilization/SLO), scope, input fidelity, predicate version, expected bool/threshold, actual evidence, counterexample, unknown on unsupported, owner, schedule, last verified state. Use existing BN-014 baseline/candidate/approval and BN-024 effective semantics; Batfish/Minesweeper as comparative independent oracle where applicable, real lab FIB/active probes separate. What-if branch isolated from observed facts, model fault removal/config delta/traffic changes with assumptions and coverage, no production mutations; recommend only, lab execution explicitly scoped later. Service recovery requires independent postconditions with stability window, not alarm quiet or ticket close. Reopen if relapse; separate actual result, operator acknowledgment and notification delivery.

## 7. Specialist workflows and closed-loop operating discipline

Reuse AG-08 persisted investigation queue and existing workflow/approval primitives; no six agents/microservices mandated. Define named typed specialists: incident correlator (always-on deterministic), evidence collector (budgeted), fault-family diagnostic (phase gated), service impact (deterministic), report/dashboard (typed display), ITSM and communications (draft by default), procedure/skill author (draft/test). One shared incident context/checkpoint with scope, version, evidence handles and decisions, not raw prompts or unrestricted global memory. Plan bounded DAG: acquire minimum evidence -> localize fault family -> test hypotheses -> obtain contrary evidence -> verify claim -> propose safe next check -> report/hand off. Escalate to approved read-only probes or human when information insufficient, not unrestricted shell, device access or arbitrary tool URLs. Track task state, queue leases/cursor, retries/cancel, caps and no duplicated work; deterministic critical path runs without model, LLM optional for interpretation and draft planning. Phase gates independent of LLM. Add event-triggered, schedule, operator and external request triggers (dedup/replay, policy and budget per tenant). One active incident owner/lock where needed, protect ingestion.

ITSM integration should link one stable internal incident to external ticket IDs (existing ServiceNow EM/change paths), explicit mapping of multiple correlated alerts vs distinct incidents, update idempotently with causal artifact and scope, external state conflicts and manual overrides, no silent close, retries/outbox per PR #35. Jira/PagerDuty/Teams/Slack optional later via scoped destinations, dedup/notification policy/on-call, approved sanitized summaries and delivery acknowledgements; no arbitrary ChatOps auth or action callbacks. Handoff report includes what happened, affected service, verified facts, unknowns, pending steps, owner and check results; no private model reasoning required. Case memory retains adjudicated incidents, evidence fingerprints, procedure version, outcomes, failed approaches and topology/context compatibility; retrieval similarity not truth, tenant boundary and TTL, replay test before adding a skill. Feedback is candidate label until independently reviewed. Start no autonomous ITSM writes; mock delivery or authorized narrowly scoped operational notifications only, explicit approval for actual external actions and no device writes. Any later closed-loop network actuation separately authorized under BN-001/002/014 with signed plan/checkpoint, locks, invariants, preconditions, bounded rollout, kill/reconcile/rollback and independent postchecks.

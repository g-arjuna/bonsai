## 1. Issue Encountered: Managed Sidecar Startup Flakiness & Stale Status

### Symptoms
1. On initial boot of Bonsai core, the python sidecar child is spawned (indicated in logs) but is immediately terminated.
2. The endpoint `GET /api/sidecar/status` shows no registered sidecars: `{"sidecars":[]}`.
3. The endpoint `GET /api/sidecar/process-status` reports that the process is still running with a stale PID (e.g. `1403924`):
   ```json
   {"state":"running","pid":1403924,"restart_count":0,"last_exit_code":null,"uptime_secs":51}
   ```
4. Calling `POST /api/sidecar/start` or `POST /api/sidecar/restart` starts the python process, but the process runs without a background supervisor loop (if it crashes, it will not restart).

### Root Cause Analysis (RCA)
- **Immediate Sender Drop**: In [src/server_startup.rs](file:///home/arjuna/Desktop/bonsai/src/server_startup.rs#L1596), the supervisor's watch channel is instantiated as:
  ```rust
  let (_, shutdown_rx) = tokio::sync::watch::channel(false);
  ```
  Because the sender is bound to `_`, it is immediately dropped by the compiler, closing the watch channel.
- **Premature Supervisor Exit**: Inside `run_supervised` in [src/sidecar_manager.rs](file:///home/arjuna/Desktop/bonsai/src/sidecar_manager.rs#L146), the loop selects on `shutdown_rx.changed()`. Because the channel is closed, `changed()` resolves immediately.
- **Silent Termination**: The supervisor executes its shutdown arm, calling `c.start_kill()` on the child process, and returns. This kills the auto-started sidecar immediately on boot and drops supervision.
- **Stale State**: Because the supervisor loop exits via `return` without updating `self.inner`, the status in the manager's memory remains permanently stuck in the `Running` state with the stale `pid`.

## 2. Suggestions for Implementation (Developer Task)

To solve this supervision and lifecycle gap, the following modifications are recommended:

### A. Move Supervision to `SidecarProcessManager`
Instead of manually spawning the supervisor task in `server_startup.rs` and passing a temporary `shutdown_rx`, make `start()` self-contained so that it subscribes to its own persistent `shutdown_tx` and spawns `run_supervised` automatically.

Modify `SidecarProcessManager::start` in `src/sidecar_manager.rs`:
```rust
    pub async fn start(self: &Arc<Self>) -> Result<()> {
        let mut guard = self.inner.lock().await;
        if guard.state == SidecarProcessState::Running
            || guard.state == SidecarProcessState::Starting
        {
            return Err(anyhow::anyhow!("sidecar is already running (pid {:?})", guard.pid));
        }
        guard.state = SidecarProcessState::Starting;
        drop(guard);
        self.spawn_child().await?;

        // Automatically spawn the supervisor task using the persistent shutdown_tx channel
        let shutdown_rx = self.shutdown_tx.subscribe();
        Arc::clone(self).run_supervised(shutdown_rx);
        Ok(())
    }
```

### B. Fix `stop()` to Signal by PID when Child Handle is Taken
Since the supervisor loop takes the child process handle out of the lock (`guard.child.take()`), the `stop()` method finds `guard.child` is `None` and fails to terminate it. We should use the stored `pid` to send a `SIGTERM` (signal 15) using the system `kill` command.

Modify `SidecarProcessManager::stop` in `src/sidecar_manager.rs`:
```rust
    pub async fn stop(&self) -> Result<()> {
        let mut guard = self.inner.lock().await;
        match guard.state {
            SidecarProcessState::Running | SidecarProcessState::Starting => {
                guard.state = SidecarProcessState::Stopping;
                if let Some(child) = guard.child.as_mut() {
                    child.start_kill().context("SIGTERM to sidecar")?;
                    info!("sent SIGTERM to sidecar (pid {:?})", guard.pid);
                } else if let Some(pid) = guard.pid {
                    // Child handle taken by supervisor loop; send SIGTERM via PID
                    let mut kill_cmd = tokio::process::Command::new("kill");
                    kill_cmd.arg("-15").arg(pid.to_string());
                    match kill_cmd.status().await {
                        Ok(status) if status.success() => {
                            info!("sent SIGTERM to sidecar via PID {:?}", pid);
                        }
                        Ok(status) => {
                            warn!("failed to send SIGTERM to sidecar PID {:?}: exit status {:?}", pid, status);
                        }
                        Err(e) => {
                            warn!("failed to execute kill command for sidecar PID {:?}: {:?}", pid, e);
                        }
                    }
                }
                Ok(())
            }
            _ => Err(anyhow::anyhow!("sidecar is not running")),
        }
    }
```

### C. Improve `restart()` Polling
In `src/sidecar_manager.rs`, modify `restart()` to wait/poll for the state to transition to `Stopped` (to ensure the old process and supervisor have cleanly exited) before launching `self.start()` again.
```rust
    pub async fn restart(self: &Arc<Self>) -> Result<()> {
        let _ = self.stop().await;
        // Wait for the state to transition to Stopped (up to 5 seconds)
        for _ in 0..50 {
            {
                let guard = self.inner.lock().await;
                if guard.state == SidecarProcessState::Stopped {
                    break;
                }
            }
            tokio::time::sleep(Duration::from_millis(100)).await;
        }
        self.start().await
    }
```

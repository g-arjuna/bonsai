## 1. Issues Encountered: ML Job Scheduling Silent Failure

### Issue A: Serialization Error with Lambda triggers
- **APScheduler 4.x SQLAlchemy Backend**: The sidecar uses `SQLAlchemyDataStore` with an SQLite database (`runtime/ml_jobs.db`). In APScheduler 4.x, schedules stored in a database backend must be fully serializable.
- **Non-Serializable Lambda Functions**: In [python/bonsai_ml/job_engine.py](file:///home/arjuna/Desktop/bonsai/python/bonsai_ml/job_engine.py), the scheduler adds schedules using a lambda trigger:
  ```python
  await self._scheduler.add_schedule(
      lambda jid=job_id: asyncio.ensure_future(self._run_job(jid)),
      trigger,
      id=job_id,
      conflict_policy="replace",
  )
  ```
- **Silent Debug Invisibility**: Since python lambda functions are not importable, APScheduler fails to serialize them and throws a `SerializationError`. This is caught by `except Exception as exc` in `_register_schedule` and logged as a `DEBUG` level log.

### Issue B: Invalid Cron Expressions for Hourly Intervals
- **Cron Conversion Bug**: In `job_engine.py`, default interval-based schedules are converted to cron expressions to be registered in the API database:
  - For example, `config_embedding` is scheduled for `hours=6` (360 minutes), and `graph_snapshot` is scheduled for `hours=4` (240 minutes).
  - The function `_schedule_to_cron` converted these hourly intervals using `f"*/{total_minutes} * * * *"` which yielded `*/360 * * * *` and `*/240 * * * *`.
- **Validation Failure**: The minute field in standard cron must be in the range `0-59`. Since `360` and `240` are outside this range, APScheduler fails to validate them, raising a validation warning:
  ```
  JobEngine: Could not register schedule for config_embedding: Error validating expression '*/360': the step value (360) is higher than the total range of the expression (59)
  ```

## 2. Implemented Fixes (Session 3)

The following changes were applied to [python/bonsai_ml/job_engine.py](file:///home/arjuna/Desktop/bonsai/python/bonsai_ml/job_engine.py):

### A. Global Engine Reference and Module-Level Function
Defined a module-level variable `_global_engine` and a serializable module-level trigger function `_trigger_job_from_scheduler` that calls the active engine's `_run_job`:
```python
_global_engine: Optional[BonsaiJobEngine] = None

async def _trigger_job_from_scheduler(job_id: str) -> None:
    """Module-level serializable function for APScheduler 4.x.
    Calls the global engine instance to run the job.
    """
    global _global_engine
    if _global_engine:
        await _global_engine._run_job(job_id)
    else:
        logging.getLogger(__name__).error(
            "JobEngine: _trigger_job_from_scheduler called but _global_engine is not set"
        )
```

### B. Store Instance Reference on Init
Set `_global_engine = self` in `BonsaiJobEngine.__init__`.

### C. Update Schedule Registration to Pass Arguments
Replaced the lambda function with `_trigger_job_from_scheduler` and passed `job_id` via `args`:
```python
            await self._scheduler.add_schedule(
                _trigger_job_from_scheduler,
                trigger,
                id=job_id,
                args=[job_id],
                conflict_policy="replace",
            )
```

### D. Elevate Registration Failures Log Level
Elevated the exception log level from `DEBUG` to `WARNING` to ensure any future schedule registration issues are immediately visible in the logs:
```python
        except Exception as exc:
            log.warning("JobEngine: Could not register schedule for %s: %s", job_id, exc)
```

### E. Fix Hourly Cron Expression Conversion
Modified `_schedule_to_cron` so that hourly intervals that are multiples of 60 minutes are converted to valid hour-based step expressions (e.g. `0 */6 * * *` instead of `*/360 * * * *`):
```python
        if total_minutes >= 60 and total_minutes % 60 == 0:
            total_hours = total_minutes // 60
            return f"0 */{total_hours} * * *"
        return f"*/{total_minutes} * * * *"
```
